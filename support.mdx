## Support by plan

| Plan | What you get |
|------|----------------|
| Soft launch / anonymous URL (no key) | **Self-serve only** — docs, [tutorial](https://geometry.app/tutorial/), site search |
| Portal metered Free | **Self-serve only** — same docs + portal key/billing self-serve |
| **Paid** (Starter and above) | Self-serve **plus** GitHub Issues for product / connectivity failures (no SLA yet) |

This matches common SaaS practice: free tiers get documentation and community-style self-serve; **ticketed human support is for paying customers**. There is no public support email.

GitHub cannot block Issue creation by plan on a public repo. Policy: Issues from non-paying use are **closed** with a pointer back here. Prove paid by stating your **Developer Portal account email** (the one on the Stripe / portal subscription) — never paste a `zpka_` key.

## When paid users may open a GitHub Issue

**Use Issues for product / connectivity failures**, for example:

- HTTP 5xx, timeouts, empty or truncated responses
- Client cannot complete the MCP handshake after following [Quickstart](/quickstart)
- A tool throws or returns malformed JSON (missing required keys, not “I expected a different sign”)

**Do not open Issues for** zodiac / calendar disagreements — read [Astro wheels](/astro-wheels) and [When it covers → Calendar boundaries](/coverage#calendar-boundaries) first. The catalog and wheels are pre-validated; different systems are supposed to diverge.

**Open an issue (paid only):** [github.com/goqolabs/geometry-mcp/issues](https://github.com/goqolabs/geometry-mcp/issues/new) — title it clearly (e.g. `Bug: mcp.geometry.app returns 502 on get_card_for_birthdate`) and include your portal account email in the body.

## Make a bug report worth filing

Incomplete reports get closed or delayed. Include:

| Include | Example |
|---|---|
| What failed | `502` / timeout / empty body / MCP connect error |
| Tool name and exact inputs | `get_card_for_birthdate`, `birth_date: 1985-03-15` |
| Client + URL shape | e.g. Cursor · paid URL with `?key=` (do not paste the key) |
| Portal account email | proves paid eligibility |
| Time (UTC) and any request id if you have one | when the 5xx happened |
| For malformed JSON only: the `_no` values from the broken block | `system_no: 16021`, `planet_no: 8` |

Those `_no` fields are opaque ids — not a public API contract (see [Field glossary](/field-glossary)) — but quoting them helps reproduce a broken payload shape.

## Leaked key

1. **Roll** the key in the Developer Portal immediately — [Where your key goes → Rotation](/connect-and-keys#rotation).  
2. Update your connector URL to the new key.  
3. The old key stays valid for **7 days** (Zuplo grace). That is normal vendor behavior.

Almost every leak is fully handled by steps 1–2. Early kill before the grace window is rare — see [Where your key goes](/connect-and-keys#if-your-key-was-exposed).
