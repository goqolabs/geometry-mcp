Technical and product questions go through **GitHub Issues** on the public docs repo. That keeps a searchable thread and avoids a public support inbox.

**Open an issue:** [github.com/goqolabs/geometry-mcp/issues](https://github.com/goqolabs/geometry-mcp/issues/new/choose) — pick **Question**, **Bug report**, or **Urgent key revoke**

## What to use Issues for

- How to connect MCP / tools / payloads  
- Docs gaps or wrong examples  
- Suspected product bugs (describe date, tool, and what you expected)  
- **Urgent key revoke** after a leak — open a new issue titled `[urgent] key revoke` (do **not** paste the `zpka_` key)

## What not to use Issues for

| Topic | Where |
|-------|--------|
| Card / invoices / cancel | Stripe billing portal (from the Developer Portal) |
| Plan changes | Developer Portal → pricing |
| Key rotation (normal) | Portal → **Roll API Key** (Zuplo issues the new key) |

## Make a bug report reproducible

The fastest reports include the **exact inputs** and the **catalog numbers** from the response:

| Include | Example |
|---|---|
| Tool name and inputs | `get_card_for_birthdate`, `birth_date: 1985-03-15` |
| The `_no` values from the block that looks wrong | `system_no: 16021`, `planet_no: 8`, `element_no: 1700` |
| What you expected vs what you got | "expected runes sign for March; got `sign_name: "none"`" |

Those `_no` fields are internal catalog identifiers — you shouldn't build on them (see [Field glossary](/field-glossary)), but quoting them lets us reproduce your exact case immediately instead of guessing which system or deck you meant. Display names can repeat across systems; the numbers can't.

## Tips

- Prefer one issue per question.  
- Link the docs page you were on if it helps.  
- A free GitHub account is required to open Issues.
