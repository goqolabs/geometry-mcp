</Info>

Two birth dates in → both identities, connections between them, and a scored breakdown. Scoring follows the cardology connection system (Cards of Destiny / Robert Camp tradition).

<Info>
  **When to use:** comparing **two** people only. For a single date’s moon, season, Rx, calendars, weekday, leap year, or day_ruler → [`get_birthdate`](/tools/get-birthdate).
</Info>

<Info>
  **One call returns** two full birth profiles plus a weighted compatibility score and cross-wheel aspects — ~1,500 deterministic fields from two dates.
</Info>

| | |
|---|---|
| **Input** | `birth_date_a`, `birth_date_b` (YYYY-MM-DD) |
| **Range** | Same coverage bands as [`get_birthdate`](/tools/get-birthdate) — `temporal_context.birth_date_a/b.band` = `full` inside 1900–2100; `extended` nearby; farther out → `out_of_range` with `payload_scope=birth_card_only` |
| **MCP URL** | `https://mcp.geometry.app/mcp` |

**Ask:**

> How compatible are people born 1985-03-15 and 1990-11-08?

Live payloads are large (~85 KB) because each side embeds a full birth profile. Below is a teaching excerpt — `birth_card_a` / `birth_card_b` are abbreviated; on the wire they match [`get_birthdate`](/tools/get-birthdate) shape.

**Full payload / raw JSON:** call this tool — live response is the complete object (no verbosity flag). Chat may summarize; ask for the raw tool result if the UI truncates.
