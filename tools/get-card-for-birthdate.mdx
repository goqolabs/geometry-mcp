# get_card_for_birthdate

One birth date in → the full cosmic identity out: birth card, ruling planet, card class, plus layered systems for that date (tarot, medicine, Lenormand, runes, ogham, geomancy, sidereal, moon phase, season, retrogrades, and more).

| | |
|---|---|
| **Input** | `birth_date` (YYYY-MM-DD) |
| **Range** | `1900-01-01` … `2100-12-31` → `temporal_context: "full"` |
| **MCP URL** | `https://mcp.geometry.app/mcp` |

**Ask (summary):**

> Get the card for birthdate 1985-03-15.

**Ask (raw JSON / full payload — dogfood-proven in Claude Desktop):**

> give raw json for birthdate 1985-03-15 card

That phrase calls `get_card_for_birthdate` and tells the **agent** to paste the tool result verbatim (not summarize). There is still only one tool input: `birth_date`. “Raw JSON” and “full payload” are the same object.

geometry.app shows a **teaching excerpt** only. This page is a public docs sample (values from a live call; season anchors verified). The sample below is **teaching shape** — shorter than the wire. Your Claude paste for the same date includes the full blocks (`medicine`, `lenormand`, full `astro_wheels`, full `retrogrades_active`, …).

**Full payload / raw JSON:** the tool always returns the complete object. RAG builders and HTTP clients read that response body directly. Chat UIs may need the “raw json” line above so the model does not trim.

## Out of published range

Dates outside 1900–2100 return a soft envelope (`temporal_context` other than `"full"`), not a crash. Birth-card identity remains month/day based.
