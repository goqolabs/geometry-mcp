A name string in → per-word and full-name **Francis Bacon** cosmic cards, Latin cipher suite sums, Chaldean `periodic{}`, and multi-cipher `periodic_set{}` (chaldean / ordinal / reduction).

<Info>
  **When to use:** a person or word **name** only. Not for dates, moon phase, season, or retrogrades — those are [`get_date`](/tools/get-date).
</Info>

| | |
|---|---|
| **Input** | `full_name` (text) — whitespace-separated words |
| **Cipher** | **41** (`francis_bacon`) → `card_no` 1–52; other Latin ciphers as raw sums |
| **Version** | `v2.3.0` |
| **MCP URL** | `https://mcp.geometry.app/mcp` |

**Ask:**

> Decode the name KEEL with get_name

**Ask (raw JSON):**

> give raw json for get_name KEEL

Live payloads also carry glyph fields on `periodic` (including `alchemical_symbol`). Prefer the live tool result for glyphs — see the Unicode warning above.

## Warning — rare Unicode glyphs in chat copies

`periodic.alchemical_symbol` uses characters from the Unicode **Alchemical Symbols** block (U+1F700–U+1F77F) and classical planetary glyphs. Those are **correct in the live MCP / HTTP response**.

When an LLM **retypes or “saves” JSON into a chat file**, it often **substitutes lookalike emoji** for those rare glyphs. Numbers, names, cards, and cipher sums usually stay intact — only the glyph field flips.

| Live tool response | Corrupted chat copy (example) |
|---|---|
| Phosphorus `🝁` **U+1F741** | `🩁` U+1FA41 |
| Oxygen `🜊` **U+1F70A** | `🌊` U+1F30A |

**This is not a GEOMETRY data bug.** Trust the live tool response. Prefer asking the model to paste the **tool result unchanged**, or verify with codepoints (`U+1F70A`). Same hazard on Claude, ChatGPT, and other LLMs. Details: [FAQ](/faq#llm-unicode-glyphs).

## What you get

- Top-level `cipher_legend[]` (Latin suite metadata once)
- `words[]` — one entry per word plus a `"full"` aggregate
- Each word: Francis Bacon `card{}`, `arcs{}`, `archetype{}`, legacy `periodic{}` (Chaldean), `periodic_set{}` (chaldean / ordinal / reduction), `ciphers[]`
