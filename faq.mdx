**What is MCP?**  
The Model Context Protocol — an open standard that lets AI apps call external tools. Add GEOMETRY once; any MCP client (Claude, ChatGPT, Cursor, and others) can query it mid-conversation.

**What is RAG?**  
Retrieval-Augmented Generation — an AI pattern that fetches facts from a tool or database before answering, instead of inventing them.

**Do I need an account to try?**  
No. Paste `https://mcp.geometry.app/mcp` and ask. Plans and keys apply when you want a metered Free plan or paid tier — see [Where your key goes](/connect-and-keys).

**Which AI client should I use?**  
**Prefer Claude** (Claude Code or Claude Desktop) for natural-language questions. Enable Geometry once; Claude usually stays in-thread and picks the right tool. **ChatGPT works** on the same URL — use `@geometry Call get_…`, and start a **new chat if the tool drops** (see below). Cursor / Codex / VS Code are fine for builders who already live there.

**ChatGPT installed geometry — why won’t it use the tool?**  
Skip the Plugins **+** chip. Type **`@geometry`**, then **`Call get_date for …`** (name the tool). The **+** chip often vanishes mid-thread. If a later turn says the tool “isn’t available,” start a **new chat** (not a GEOMETRY outage). Claude does not need `@` after one enable. Full steps + quirk table: [Quickstart → ChatGPT](/quickstart#chatgpt-plugins) · [known quirks](/quickstart#chatgpt-known-quirks).

**When should I start a new ChatGPT chat?**  
When invoke fails or the tool drops mid-thread (list ≠ invoke). Observed July 2026: a thread that worked after one tool call can fail on a later ask. Geometry’s MCP URL and tools are fine; Claude usually keeps the connector in one thread. Ops rule: always `@geometry`; **new chat when invoke fails**. Prefer Claude for demos and non-technical “just ask.”

**ChatGPT called the wrong tool for moon / retrogrades / leap year?**  
Use **`get_date`** for any single-date fact (moon, season, Rx, `calendar_meta`, `day_ruler`). Prefer a **new chat** and `@geometry Call get_date …`. Routing: [Quickstart → Then ask your AI](/quickstart#then-ask-your-ai).

**Claude vs ChatGPT — same MCP URL?**  
Yes — `https://mcp.geometry.app/mcp`. **Claude** = recommended NL path. **ChatGPT** = supported — use `@geometry Call get_…`, and a **new chat if the tool drops**. See [Quickstart](/quickstart).

**Is there a REST / HTTP API?**  
Yes as a **secondary** surface — same tools and JSON as MCP. Prefer MCP for AI clients. Branded `api.geometry.app` curl/SDK docs land later; see [HTTP API](/http-api).

**Is the data stable?**  
Yes. The date range and its systems are pre-computed and versioned — same call, same answer today, tomorrow, and next year. **Public beta** means tooling and quotas are still evolving, not that the data drifts. See [Quickstart](/quickstart).

**What are the calendar boundaries?**  
Published coverage is **1900-01-01** through **2100-12-31**. Within that window, bare `YYYY-MM-DD` fields can mean different things — cultural year starts vs GMT sky-event days. Full explanation: [When it covers → Calendar boundaries](/coverage#calendar-boundaries).

**What's cardology?**  
A date-to-playing-card system (Cards of Destiny tradition) with a relationship / connection layer. GEOMETRY serves a machine-readable version of it — each month/day maps to one **Cosmic card**.

**Is this astrology? Do you claim it predicts anything?**  
GEOMETRY serves the *data* of traditional symbolic systems — deterministically. Interpretation belongs to your product.

**What does it cost?**  
Soft launch: free MCP URL, no account. Metered Free and paid plans roll out with self-serve billing in the Developer Portal. Current prices are shown in the portal when plans are live.

**Where is my data stored? Do you see my users' questions?**  
GEOMETRY is a read-only reference lookup. Calls take dates or names (tool inputs), return JSON, and are not used to build user profiles.

**Where is the full JSON / contract?**  
Docs samples are shortened on purpose. Every successful tool call returns the **complete** JSON. For [`get_date`](/tools/get-date), the only input is `date` — there is no `full=true` flag. “Full payload” and “raw JSON” mean that complete object.

**How do I see the full JSON in chat?**  
Ask something like: `give raw json for date 1985-03-15 card`. That tells the agent to paste the tool result instead of summarizing. If you read the MCP or HTTP response in code, you already have the full object.

**Why does `alchemical_symbol` look like a water wave or garbage emoji in a JSON file my AI saved?**  
The live tool is fine. Rare Unicode glyphs (especially U+1F700–U+1F77F alchemical symbols) often get **rewritten incorrectly** when an LLM regenerates or “exports” JSON from memory. Verified case (2026-07-28): live `get_name` returned phosphorus `🝁` (U+1F741) and oxygen `🜊` (U+1F70A); a chat-saved copy flipped those to `U+1FA41` and `🌊` (U+1F30A). Cards, cipher sums, element names, and atomic numbers in that same file still matched the engine.

**What to trust:** the live MCP/HTTP tool response — not a hand-rewritten chat artifact. **What stays reliable in those copies:** ordinary text and numbers. **What to double-check:** glyph fields (`alchemical_symbol`, and any other rare symbols). Ask the model to paste the tool output **without rewriting**, or check codepoints. See [`get_name`](/tools/get-name#warning--rare-unicode-glyphs-in-chat-copies).

**Which timezone decides when a cultural year starts?**  
It depends on the system. Chinese and Vietnamese lunar years use **CST** (UTC+8), Vedic samvatsara uses **IST** (UTC+5:30), Hebrew and Dreamspell are **timezone-neutral**, and Persian uses the equinox in **GMT**. Tools take a bare `YYYY-MM-DD` with no time or zone; no conversion runs at request time. Full table: [When it covers → Calendar boundaries](/coverage#calendar-boundaries).

**Why doesn't your Nowruz match my Persian calendar library?**  
GEOMETRY anchors Persian years to the equinox in GMT. Iran’s official Solar Hijri rule uses Tehran local time and rolls to the next day when the equinox falls after Tehran solar noon. The two disagree on roughly a quarter to a third of years — including 2026 (GEOMETRY March 20, Iran March 21). Documented convention, not a bug. See [When it covers → Calendar boundaries](/coverage#calendar-boundaries).

**How were moon / season / retrograde dates calculated?**  
Offline with the **Swiss Ephemeris** Python stack, then stored as lookups. Requests do not run a live ephemeris. Each date in the payload is the Gregorian day of the instant **in GMT**. Library: [**pyswisseph**](https://github.com/astrorigin/pyswisseph). See [When it covers](/coverage).

**Your moon phase date is one day off from mine.**  
Usually a timezone difference. GEOMETRY publishes the GMT day; a local almanac may use local time. Local dates differ roughly `offset ÷ 24` of the time — about a third of the time at UTC+8 or UTC−8. Convert in your app if you need local dates. See [When it covers → Calendar boundaries](/coverage#calendar-boundaries).

**Was that date a blue moon / blood moon / supermoon / micromoon?**  
Ask [`get_date`](/tools/get-date) for the date and read `moon_phase`. These are **deterministic calendar / ephemeris facts** from AstroPixels/BOSS anchors (GMT) — not interpretive meaning. GEOMETRY does **not** invent moon slang; it applies the same standard sky rules builders already use from NASA and almanacs.

**Where are the karmic cards and planetary spreads?**  
On the Cosmic card under `cosmic.karma` (source = past, spirit = future) and `cosmic.planetary_spread` (14 Life-spread slots: `sun` = the Cosmic card, then moon … rahu, midheaven, phoenix). Same blocks nest under wire keys `birth_card_a` / `birth_card_b` on [`get_compatibility`](/tools/get-compatibility).

**How do I sort `planetary_spread`?**  
JSON object keys are unordered. Every slot has **`spread_pos`** (1–14). Sort ascending on that field — sun=1 … midheaven=13, phoenix=14. See [get_date → Planetary spread order](/tools/get-date#planetary-spread).

**Is the Sun card different from the Cosmic card / Life card?**  
No — they are the **same card**. The date’s Cosmic face is also the Life card and the Sun slot in the planetary spread. The payload aliases that identity on the wire: `cosmic.also_called` is `["birth_card","life_card","sun_card"]`, and `planetary_spread.sun` repeats it with `is_sun_birth_card: true`.

| Flag / field | Meaning |
|---|---|
| `is_blue_moon_monthly` | Second **full moon** in the same Gregorian month (GMT day) |
| `is_blue_moon_seasonal` | Third of four full moons in one astronomical season (solstice/equinox interval) |
| `is_blood_moon` | Full moon with a **total lunar eclipse** (`eclipse_code: "lt"`) |
| `is_supermoon` | Full moon near perigee — Earth–Moon distance **&lt; 360 000 km** |
| `is_micromoon` | Full moon near apogee — Earth–Moon distance **&gt; 405 000 km** |
| `earth_moon_distance_km` | Distance (km) on that phase day; `0` if not a moon-phase anchor |
| `apparent_diameter_arcmin` | Apparent lunar diameter (arcminutes); `0` if not an anchor |
| `phase_gmt` | Exact phase instant as `HH:MM:SS` **GMT**; `"none"` if not an anchor |
| `prev_*` / `next_*` | Nearest earlier/later **monthly blue** or **blood** dates (`"none"` at catalog edges) |

**Supermoon (NASA + standard numeric lock):** NASA describes a supermoon as a **full Moon near perigee** (closest approach in the elliptical orbit) — not an official IAU term, but the concept is standard ([NASA Science — Supermoons](https://science.nasa.gov/moon/supermoons/)). GEOMETRY does the same thing: full-moon day **and** distance under the widely published almanac threshold **&lt; 360 000 km** (same numeric rule TimeandDate publishes). We are **not** inventing a private formula — one repeatable answer for builders. Boundary honesty: **2018-01-31** is blood + monthly blue at **360 199 km**, so `is_supermoon` is **false** under that lock (media often still branded it “super”).

**Micromoon:** the far-side twin — full moon **and** distance **&gt; 405 000 km** (near apogee; same threshold family as TimeandDate).

Blue moon is a calendar label, not a color. Blood moon here means **total lunar eclipse** only (not dust/haze). Month bucketing uses the same GMT civil day as other sky-event dates.

**“Wolf moon”?** January’s full moon. Agents can say that from the calendar; it is not a featured product flag.

**Why doesn’t my sign match another app?**  
GEOMETRY returns **five** wheels under `astro_wheels` (tropical, Vedic rasi, Fagan-Bradley, sidereal IAU, true sidereal). They can disagree on the same date — that is by design, not a bug. Match the wheel your source uses. **`sidereal_iau`** and **`sidereal_true`** both use unequal widths that follow the sky; GEOMETRY recommends **`sidereal_true`** when you need a default. Full table: [Astro wheels](/astro-wheels).
